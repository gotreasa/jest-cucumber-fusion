# Getting help

## Start with the documentation

- The [README](./README.md) sets up a project from nothing, and its [Troubleshooting](./README.md#troubleshooting) list covers the errors people hit most often.
- The [documentation index](./docs/README.md) lists every guide: step arguments, tables, outlines, shared steps, options, CommonJS, TypeScript, ESLint and upgrading.

## Ask a question or report a problem

[Open an issue](https://github.com/gotreasa/jest-cucumber-fusion/issues/new/choose) and pick the form that fits:

- **Question**, for how to do something.
- **Bug report**, when Fusion does something wrong. Fill in every field: the versions, how your step files load the package, the smallest feature file and step definitions that show the problem, and what Jest printed. A problem that can be reproduced can be fixed.
- **Feature request**, for something Fusion does not do yet.

Search the [existing issues](https://github.com/gotreasa/jest-cucumber-fusion/issues?q=is%3Aissue) first: someone may have asked already.

## Not here

- **A security vulnerability**: do not open an issue. Follow the [security policy](./SECURITY.md) to report it privately.
- **Behaviour that breaks the [code of conduct](./CODE_OF_CONDUCT.md)**: report it privately through the [private report form](https://github.com/gotreasa/jest-cucumber-fusion/security/advisories/new), starting the title with "Code of conduct". [Reporting an Issue](./CODE_OF_CONDUCT.md#reporting-an-issue) says more.

## What to expect

This is an open-source project: there is no paid support and no guaranteed response time. Support covers the latest version 3 release; on an older version, upgrading first ([Migrating to version 3](./docs/Migrating.md)) often answers the question.
